# tui-ux-guardrails

用于 TUI 布局/视觉/交互可达性的防返工技能。目标是减少“多次小修补”的迭代噪音，提升一次性正确率。

## 触发场景

- 用户提到：`对齐`、`分组`、`上下/左右布局`、`宽窄屏`、`tab切换`、`focus`、`panel`、`视觉不一致`。
- 或者提交历史显示同一视图被短时间内反复修改（如 memory/trace/watch/dashboard 连续补丁）。

## 执行步骤

1. 冻结设计意图（先写后改）
   - 输出 3-6 条可验证约束：
     - 几何：`80 列`、`140 列`下的单/双行规则
     - 结构：是否必须拆成独立 panel
     - 交互：是否可通过 `Tab` 到达

2. 拆分任务类型
   - 结构层：`compose()` 树与容器关系、focus 链
   - 皮肤层：TCSS（边框、间距、颜色）
   - 顺序固定：先结构，后皮肤

3. 最小实现
   - 只改目标视图和必要样式，禁止跨视图顺手重构
   - 明确“保持不变”的行为（例如 40/60 split）

4. 测试策略（必须）
   - class 断言 + region 几何断言
   - 宽窄屏各至少一个尺寸（推荐 `80x24`、`140x24`）
   - 焦点变更必须测 `tab` 可达

5. 验证命令
   - `uv run ruff check <changed files>`
   - `uv run pytest tests/tui/test_style_layout.py -k "<affected views>" -v`

## 反模式（禁止）

- 只改颜色不改结构，却试图解决结构问题
- 只看截图主观判断，不补几何断言
- 在主问题未闭环前顺手改其他视图
- 连续提交多个“fix ui small issue”而不归并
