## 话题概述

该话题在同一天集中暴露出 Top 体系的两类系统性问题：一是采样过滤逻辑错误导致“采样全空”或误过滤；二是 TopView 生命周期与连接模型设计不当导致数据不显示或错乱。核心模式是“线程/连接语义误判 + 缺少流式并发约束”。

## 事故 #4：TopView 共享客户端引发套接字竞争与数据显示失败

> **Tag 范围**：`未知` → `HEAD` | **严重级别**：SEV-1 | **日期**：2026-02-26

Race Condition

## 事故 #3：TopView profiling 初始化挂在错误生命周期点

> **Tag 范围**：`未知` → `HEAD` | **严重级别**：SEV-2 | **日期**：2026-02-26

### 概要

TopView 在 `on_mount()` 内尝试启动 profiling，但此时 `set_client()` 尚未注入客户端，导致初始化被跳过且不再重试，界面长期停留 `Initializing...`。

### 根因分析

#### 类别
Integration Error

#### 分析
Textual 生命周期中，视图挂载先于父组件依赖注入。将依赖型初始化放在 `on_mount()` 会遇到 `self._client is None`。原实现缺少后续触发点。

修复策略：
- `on_mount()` 仅做 UI 初始化。
- `set_client()` 完成后调用 `_start_profiling()`。
- `_start_profiling()` 内部检查 client 可用性。

引入该 bug 的提交：

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| `未提供` | 未提供 | 未提供 | TopView 初版将 profiling 启动放在 on_mount |

### 复现

#### 前置条件
- attach 成功后进入 Top 标签。

#### 步骤
1. 打开 TopView。
2. 观察表头与数据区。

#### 预期行为
自动启动 profiling 并出现采样。

#### 实际行为
显示 “Initializing...”，表格空。

### 修复

#### 修复提交

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| `c0deb3d` | 未提供 | 2026-02-26 | fix(tui): move TopView profiling init from on_mount to set_client |

#### 变更内容
- 重排初始化职责：UI 与依赖型逻辑分离。
- 以 `set_client()` 作为 profiling 启动唯一入口。

#### 验证
- `set_client()` 调用后 profiling 自动启动。
- 表格开始显示采样数据。

### 影响

- **受影响用户**：TopView 用户。
- **持续时间**：TopView 初版至 2026-02-26。
- **数据影响**：无。

## 事故 #2：Top 线程过滤使用子字符串匹配导致误过滤

> **Tag 范围**：`未知` → `HEAD` | **严重级别**：SEV-2 | **日期**：2026-02-26

### 概要

线程过滤逻辑使用 `"peeka/" in filename` 子字符串匹配。目标程序若位于包含 `peeka` 的路径（如 `peeka-demo`），用户代码被误判为内部代码并全量过滤。

### 根因分析

#### 类别
Logic Error

#### 分析
过滤条件过宽，未区分“路径包含 peeka 字样”与“确属 peeka 包目录”。

修复前：

```python
if frame and "peeka/" in frame.f_code.co_filename:
    return True
```

修复后：

```python
# Resolve peeka package directory at init time
self._peeka_pkg_dir: str = os.path.dirname(os.path.dirname(os.path.abspath(__file__))) + os.sep

# Check with prefix matching
if frame:
    fname = frame.f_code.co_filename
    if fname.startswith(self._peeka_pkg_dir):
        return True
```

## 事故 #1：采样线程比较对象错误导致 `top` 全空结果

> **Tag 范围**：`未知` → `HEAD` | **严重级别**：SEV-1 | **日期**：2026-02-26

### 概要

`_is_peeka_thread()` 使用 `threading.current_thread() == self._sampling_thread` 判断，被调用上下文恒在采样线程内，条件恒真，导致所有线程都被过滤，`total_samples=0`。

### 根因分析

#### 类别
Logic Error

#### 分析
方法签名提供的是“被检查线程 ID”，实现却比较“当前执行线程对象”。调用上下文固定导致逻辑恒真。

修复前：

```python
if (
    self._sampling_thread
    and threading.current_thread() == self._sampling_thread
):
    return True
```

修复后：

```python
if (
    self._sampling_thread
    and self._sampling_thread.ident == thread_id
):
    return True
```

引入该 bug 的提交：

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| `未提供` | 未提供 | 未提供 | Top 实现中线程比较对象选择错误 |

### 复现

#### 前置条件
- 启动 top profiling。

#### 步骤
1. 开始采样。
2. 获取 snapshot。

#### 预期行为
返回非零采样与函数列表。

#### 实际行为
函数列表为空，`total_samples=0`。

### 修复

#### 修复提交

#### 变更内容

#### 验证

- peeka 线程被正确排除。
- 采样计数恢复非零。

### 影响
