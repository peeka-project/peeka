## 话题概述

该话题集中体现为 Memory/Logger 视图在 Textual 生命周期、线程模型与 CSS 规则上的耦合缺陷：初始化顺序导致不刷新、并发刷新导致套接字竞争、交互式 PTY 与 headless 行为分叉、以及多处 CSS 特异性/容器高度配置导致可见性与对齐问题。事故多为可恢复故障，但多次出现“功能可用性下降到接近不可用”的 SEV-1 级影响，说明该模块需要统一的刷新编排与样式约束。

## 事故 #10：并行初始刷新导致套接字竞争

> **Tag 范围**：`N/A（来源为日期归档文件）` | **严重级别**：SEV-2 | **日期**：2026-03-08

### 概要

Memory 初始加载中 overview 与 GC 并行刷新，约 30% 概率 GC 表格为空。

### 根因分析

#### 类别
Race Condition

#### 分析
同一专用客户端上并发执行：

```python
self.run_worker(self._refresh_overview(), thread=False)
self.run_worker(self._refresh_gc_objects(), thread=False)
```

即使存在 `_send_lock`，同连接并发请求仍可能导致响应错配。

#### 致因提交

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| 无法确定性定位 | 未记录 | 2026-03-08 前 | 添加自动 GC 刷新后形成并行初始化 |

### 复现

#### 前置条件
- 打开 Memory View

#### 步骤
1. 首次进入 Memory。

#### 预期行为
overview 与 GC 均稳定加载。

#### 实际行为
GC 表格间歇为空。

### 修复

#### 修复提交

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| `a7989e7` | 未记录 | 2026-03-08 | fix(tui): serialize initial refresh to avoid socket contention |

#### 变更内容

```python
async def _initial_refresh(self) -> None:
    await self._refresh_overview()
    await self._refresh_gc_objects()
```

改为串行刷新。

#### 验证
GC 初始化稳定，空表概率显著下降。

### 影响

- **受影响用户**：Memory 首次进入用户
- **持续时间**：引入并行刷新后至 `a7989e7`
- **数据影响**：无

### 时间线

| 时间 | 事件 |
|------|------|
| 2026-03-08 前 | 初始化并行刷新引入竞争 |
| 2026-03-08 | `a7989e7` 改串行 |

### 经验教训

#### 做得好的方面
- 快速由“并行优化”回退到“可靠优先”。

#### 可以改进的方面
- 同连接并发能力假设过于乐观。

#### 行动项

| 行动 | 优先级 | 状态 |
|------|--------|------|
| 明确单连接请求-响应串行约束并文档化 | P1 | 待处理 |
