## 事故 #5：无点前缀缓存导致间歇性空补全

> **Tag 范围**：`N/A（来源为日期归档文件）` | **严重级别**：SEV-2 | **日期**：2026-03-05

### 概要

输入无点前缀（如 `Calc`）时，补全结果会间歇为空。用户需反复输入才能恢复。

### 根因分析

#### 类别
Logic Error

#### 分析
无点前缀缓存键固定为 `""`，不同查询共享缓存项，后续过滤容易得到空结果。该问题在引入 `__main__` 属性搜索后更明显。

```python
has_dot = "." in prefix
cache_key = prefix[: prefix.rfind(".") + 1] if has_dot else None
if cache_key is not None and cache_key in self._cache:
    # use cache
...
if cache_key is not None:
    self._cache[cache_key] = (time.monotonic(), items)
```

#### 致因提交

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| 无法确定性定位 | 未记录 | 2026-03-05 前 | 无点前缀使用共享缓存键的初始设计 |

### 复现

#### 前置条件
- 自动补全缓存已命中一次无点前缀

#### 步骤
1. 搜索 `Cal` 获取结果。
2. 搜索 `Calc`。

#### 预期行为
第二次查询返回更精确候选。

#### 实际行为
复用错误缓存后过滤为空。

### 修复

#### 修复提交

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| `9dfee1e` | 未记录 | 2026-03-05 | fix(tui): disable cache for undotted prefixes to fix intermittent empty completions |

#### 变更内容
禁止无点前缀缓存，仅对带点模块路径启用缓存。

#### 验证
无点前缀每次返回正确补全，不再间歇空列表。

### 影响

- **受影响用户**：TUI 自动补全用户
- **持续时间**：缓存逻辑引入后至 `9dfee1e`
- **数据影响**：无

### 时间线

|------|------|
| 2026-03-05 前 | 无点前缀共享缓存键 |
| 2026-03-05 | `9dfee1e` 禁用无点前缀缓存 |

### 经验教训

#### 做得好的方面
- 修复精准切断了错误复用路径。

#### 可以改进的方面

## 事故 #4：自动补全需输入两个字符才触发

> **Tag 范围**：`N/A（来源为日期归档文件）` | **严重级别**：SEV-3 | **日期**：2026-03-05

### 概要

补全触发被硬编码为 `len(prefix) >= 2`，单字符输入无法给出候选，降低交互效率。

### 根因分析

#### 类别
Logic Error

#### 分析
人为阈值假设与用户预期冲突。现代补全通常从首字符开始反馈。

**修改前：**
```python
if not prefix or len(prefix) < 2:
    return
```

**修改后：**
```python
if not prefix:
    return
```

#### 致因提交

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| 无法确定性定位 | 未记录 | 2026-03-05 前 | autocomplete widget 初始阈值策略 |

### 复现

#### 前置条件
- 任意补全输入框

#### 步骤
1. 输入 `C`。

#### 预期行为
立即弹出补全列表。

#### 实际行为
无补全，需继续输入到 `Ca`。

### 修复

#### 修复提交

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| `9c3623d` | 未记录 | 2026-03-05 | fix(tui): enable autocomplete from first character typed |

#### 变更内容
去除 `len(prefix) < 2` 限制，仅在空前缀时返回。

#### 验证
首字符输入即可触发补全。

### 影响

- **持续时间**：初始实现至 `9c3623d`

## 事故 #2：补全未覆盖 `__main__` 与用户脚本符号

> **Tag 范围**：`N/A（来源为日期归档文件）` | **严重级别**：SEV-2 | **日期**：2026-03-05

### 概要

直接运行脚本时，用户代码位于 `__main__`。补全系统过滤下划线模块导致 `__main__` 被排除，用户需输入 `__main__.` 才能看到候选，严重影响可用性。

### 根因分析

#### 类别
Missing Validation

#### 分析
模块过滤规则未覆盖 Python 常见运行模式（`python script.py`）。同时无点前缀检索未搜索 `__main__` 属性。

#### 致因提交

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| 无法确定性定位 | 未记录 | 2026-03-05 前 | 自动补全初始实现过滤 `__main__` |

### 复现

#### 前置条件
- 脚本中定义 `class Calculator` 并直接运行

#### 步骤
1. 输入 `Calc`。

#### 预期行为
返回 `__main__.Calculator` 等候选。

#### 实际行为
无结果，需手输 `__main__.`。

### 修复

#### 修复提交

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| `7d3f678` | 未记录 | 2026-03-05 | fix(commands): include __main__ and its attributes in autocomplete results |

#### 变更内容

2. 无点前缀额外检索 `__main__` 属性并返回 `__main__.attr_name`。
3. 按 `comp_type` 过滤 classes/functions。

#### 验证
无需输入 `__main__.` 即可补全用户类/函数。

### 影响

## 事故 #1：CompletionSource 多缺陷导致补全链路不可用

> **Tag 范围**：`N/A（来源为日期归档文件）` | **严重级别**：SEV-2 | **日期**：2026-02-07

### 概要

补全系统初版同时存在客户端类型错误、异步签名错误、参数键错误、notify 严重级别非法、时间 API 不当，导致补全不工作并伴随异常日志。

### 根因分析

#### 类别
Integration Error

#### 分析
关键接口契约与 Textual/命令层协议不一致：
1. `AgentClient`/`StreamingAgentClient` 类型不匹配。
2. `get_completions` 被定义为 `async`，但调用方要求同步。
3. `complete` 命令参数错误：`type` 应为 `completion_type`。
4. `notify` 使用非法 severity `success`，应为 `information`。
5. 同步路径中不应依赖 `asyncio.get_event_loop().time()`，改为 `time.monotonic()`。

#### 致因提交

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| 无法确定性定位 | 未记录 | 2026-02-07 前 | 自动补全初始实现存在多处接口契约错误 |

### 复现

#### 前置条件
- TUI 任何支持补全的输入框

#### 步骤
1. 输入前缀。
2. 观察补全列表与日志。

#### 预期行为
稳定弹出候选，通知系统无异常。

#### 实际行为
补全不出现或异常，notify 报级别错误。

### 修复

#### 修复提交

| 提交 | 作者 | 日期 | 描述 |
|------|------|------|------|
| `531e0fe` | 未记录 | 2026-02-07 | fix(tui): fix CompletionSource bugs and invalid severity |

#### 变更内容
1. 客户端类型：`AgentClient` → `StreamingAgentClient`。
2. 方法签名：`async def get_completions` → `def get_completions`。
3. 时间源：`asyncio.get_event_loop().time()` → `time.monotonic()`。
4. 参数键：`"type": "all"` → `"completion_type": "all"`。
5. `notify` 级别：`success` → `information`。

#### 验证
补全候选正常出现，通知系统无非法级别报错，缓存行为正常。

### 影响

- **受影响用户**：所有 TUI 自动补全用户
- **持续时间**：初始实现至 `531e0fe`
- **数据影响**：无
