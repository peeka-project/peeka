## 话题概述

该话题反映了安全控制中的关键失效模式：条件表达式安全评估抛异常后，观测仍被创建，未遵循“失败即拒绝（fail-closed）”原则。同时测试用例预期方向被写反，导致缺陷未被测试体系正确阻断。修复通过在 `should_observe()` 中将异常路径明确返回 `False`，并同步修正测试预期，恢复安全边界。

## 事故 #1：危险条件评估失败后观测仍被创建

> **Tag 范围**：`未提供` → `未提供` | **严重级别**：SEV-0 | **日期**：2026-01-29

### 概要

当条件表达式包含危险代码（如 `__import__`、危险对象属性访问）时，`simpleeval` 已抛出异常，但系统仍创建观测，违反安全设计预期。该缺陷被归类为安全漏洞，需以 fail-closed 语义修复。

### 根因分析

#### 类别
Logic Error

#### 分析
`should_observe()` 对条件评估异常处理错误：异常未被正确阻断到“拒绝观测”路径，或捕获后仍返回允许值。来源文件指出异常处理逻辑在安全场景下未达成预期。并且测试用例预期写反，误将该异常路径视为正常行为，削弱了防线。

修复核心代码片段（原文保留）：

```python
try:
    result = self.eval(expr)
except Exception:
    return False
```

### 复现

#### 前置条件
- 条件表达式由 `simpleeval` 执行安全评估
- 旧版 `should_observe()` 异常路径未 fail-closed

#### 步骤
1. 使用条件表达式 `output=os.system('rm -rf /')`。
2. 触发条件评估。
3. 观察异常后的观测创建行为。

#### 预期行为
危险条件评估失败后，不应创建观测。

#### 实际行为
`simpleeval` 抛异常后，观测仍被创建。

#### 变更内容
1. 在 `should_observe()` 中，条件评估失败时返回 `False`。  
2. 修正测试预期：注入可成功，但危险条件评估失败时不应产生观测。

#### 验证
- 危险条件评估失败 -> `should_observe()` 返回 `False` -> 不创建观测。  
- 安全条件继续正常工作。  
- 安全拦截链路恢复。
